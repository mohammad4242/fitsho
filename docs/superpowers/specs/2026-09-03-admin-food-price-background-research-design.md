# Admin Food Price Background Research Design

## Goal

وقتی مدیر روی «استعلام قیمت» در کاتالوگ مواد غذایی کلیک می‌کند، همان صفحه و کارت‌ها
باقی بمانند و استعلام بدون بازکردن دیالوگ انجام شود. تا پایان درخواست، کارت همان ماده
«در حال استعلام» را نشان می‌دهد؛ در موفقیت قیمت اعمال‌شده نمایش داده می‌شود و در خطا
علت خطا روی همان کارت باقی می‌ماند.

## Scope

- فقط مسیر «استعلام قیمت» تغییر می‌کند.
- «ویرایش قیمت» دستی و دیالوگ مربوط به آن بدون تغییر باقی می‌ماند.
- صف، worker، polling یا endpoint جدید Backend ساخته نمی‌شود.
- endpoint فعلی `POST /api/v1/nutrition/admin/foods/{slug}/price-research?apply=true`
  مرجع اعمال قیمت است؛ Backend همچنان قیمت نهایی را normalize و persist می‌کند.

## Architecture and data flow

1. `FoodCataloguePage` وضعیت استعلام را با کلید `food.slug` نگه می‌دارد تا چند کارت
   بتوانند هم‌زمان مستقل از هم کار کنند.
2. کلیک دکمه، بدون تغییر `priceFood`، `researchFoodPrice(slug, true)` را به‌صورت
   fire-and-handle اجرا می‌کند.
3. در وضعیت `researching` فقط همان دکمه غیرفعال و وضعیت کارت به‌صورت قابل‌دسترسی
   نمایش داده می‌شود؛ هیچ `PriceOverrideDialog` باز نمی‌شود.
4. پاسخ موفق با قیمت نامزدشده، قیمت کارت را از پاسخ اعمال خودکار به‌روزرسانی می‌کند
   تا مدیر نتیجه را فوراً ببیند. پاسخ Backend قبلاً همان قیمت را به‌عنوان override
   فعال ذخیره کرده است.
5. پاسخ `no_quotes`، `failed` یا خطای HTTP به وضعیت خطا تبدیل می‌شود و پیام پاسخ یا
   پیام پیش‌فرض محلی روی کارت نمایش می‌یابد. قیمت قبلی در خطا دست‌نخورده می‌ماند و
   دکمه برای تلاش دوباره فعال است.

## UI states

- Idle: قیمت فعلی و دکمه «استعلام قیمت».
- Researching: متن «در حال استعلام…» در بلیت قیمت، دکمه همان کارت غیرفعال.
- Success: بلیت قیمت پذیرفته‌شده با واحد تومان؛ وضعیت موقت از state حذف می‌شود.
- Failure: پیام علت با `role="alert"` روی بلیت قیمت؛ قیمت قبلی حفظ می‌شود.

## Error handling and safety

- کلیک تکراری در زمان درخواست همان ماده نادیده گرفته می‌شود.
- شکست یک ماده روی استعلام مواد دیگر اثر نمی‌گذارد.
- پاسخ موفق بدون قیمت معتبر موفقیت تلقی نمی‌شود و پیام خطا/عدم قیمت نمایش می‌یابد.
- هیچ قیمت حدسی در UI ساخته نمی‌شود؛ قیمت فقط از `candidate_reference_price_toman`
  پاسخ Backend می‌آید.

## Testing

- تست Frontend ثابت می‌کند کلیک دیالوگ قیمت را باز نمی‌کند و درخواست با `apply=true`
  ارسال می‌شود.
- تست Frontend حالت pending را با «در حال استعلام» و غیرفعال‌شدن همان دکمه پوشش می‌دهد.
- تست Frontend موفقیت را با نمایش قیمت پاسخ و refetch نکردنِ اجباریِ صفحه پوشش می‌دهد.
- تست Frontend `no_quotes`/`failed` و خطای HTTP را با نمایش علت و حفظ قیمت قبلی پوشش
  می‌دهد.
- تست Backend موجود برای `apply=true` مرجع حفظ‌شدهٔ اعمال و persistence باقی می‌ماند.
