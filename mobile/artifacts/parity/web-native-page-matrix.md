# Web ↔ Native page matrix

Phase 0 inventory captured from the checked-out web and native source. Web owns page
information architecture and visual hierarchy. Native owns phone interaction, safe areas,
navigation, keyboard/camera/media behavior, caching, and accessibility.

## Evidence limits

This is a source-and-test inventory. No Android device or emulator was available, so the
visual width and state columns are implementation targets and source-observed behavior, not
physical-device acceptance. Every page remains `implemented-awaiting-device-check` until the
final device matrix is exercised.

Classification values follow the master plan: `VISUAL_HIERARCHY`, `SECTION_ORDER`,
`TYPOGRAPHY`, `SPACING`, `COMPONENT_SHAPE`, `COPY`, `STATE_PRESENTATION`,
`NATIVE_ADAPTATION`, `MISSING_EXISTING_CAPABILITY`, `FUNCTIONAL_BUG`, and `OUT_OF_SCOPE`.

## Equivalent-state coverage

| State | Web evidence | Native evidence | Inventory classification |
| --- | --- | --- | --- |
| Populated | Web pages map real profile, workout, nutrition, body, and specialist data | Query-backed native screens and model tests use real contract-shaped values | Baseline coverage exists; visual device check pending |
| Loading | Route fallback plus page-specific loading/empty branches | `Skeleton`, `StateSkeleton`, query `isPending`, and route guard loading surfaces | `STATE_PRESENTATION` differences are page-specific |
| Empty | Web empty estimate/plan/catalogue/dashboard states | `EmptyState` and feature-specific empty branches | Preserve action direction; do not replace with fake data |
| Error/retry | Web error sections and retry links/buttons | `Notice` plus refetch/retry actions in feature screens | Preserve safe user-facing copy and retry behavior |
| Offline/stale | Web has page-specific status; native has connectivity monitor and `getMobileViewState` | Native offline/stale notices preserve cached data where available | Native adaptation is required; do not replace page with warning-only UI |
| Pending approval/read-only | Workout coach and nutrition physician flows in web | Native workout, plan, coach, physician, and result screens model read-only states | Preserve guards and explicit status |
| Historical | Workout version history and body timeline on web | Workout history, body history, nutrition history, private local media | Preserve route/data ownership |

## Phase 0 gate

Every core page now has a row with web source, native route/implementation, preserved actions and
states, known differences, and a phase-specific allowlist. No page rebuild should begin without
updating its row with before/after evidence and the exact changed files.
